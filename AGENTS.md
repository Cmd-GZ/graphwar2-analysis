# AGENTS.md — notes for automated contributors

Read this before touching anything. The repo is small; the rules are short.

## What this repo is

A reverse-engineered, **bit-exact** reimplementation of the trajectory sampler inside
Graphwar II (`libgraphwarrust.so`), plus the toolchain used to recover and verify it.

**Scope note (2026-11).** The overall project goal is to **reconstruct the game's source code**
(so it can be read and analysed — e.g. to write strategy guides), not to ship a playable clone
and not to build a third-party open version. Producing a behaviourally identical binary is only
**step one**; source-level reconstruction (same files / modules / function boundaries) is the
finish line. **This repo is the RE toolchain half**; the source reconstruction lives in
`gw2-rebuild/` (see its `AGENTS.md` §0, which is the binding standard for that half —
including the rule that *our own tests are regression protection, not reconstruction evidence*).

* `graphwar_curve.py` — **this repo's deliverable** (the reference sampler, used as an oracle).
  Parser + evaluator + sampler + CLI. It is *not* the project's final deliverable — that is the
  reconstructed source in `gw2-rebuild/`.
  *Standard library only.* Keep it that way: no numpy, no capstone, no unicorn.
* `REPORT.md` — the authoritative write-up (Chinese). If behaviour and report disagree,
  the behaviour wins and the report is a bug.
* `analysis/` — the reverse-engineering toolchain. Nothing here is imported by
  `graphwar_curve.py`.

## Golden rules

1. **`graphwar_curve.py` must stay dependency-free and side-effect-free** on import.
2. Any behavioural change to it must keep the differential tests green
   (`analysis/difftest.py`, `analysis/fuzz.py`, `analysis/difftest_parser.py`,
   `analysis/final_verify.py`). They compare against the *real* binary, so they are the
   only real specification.
3. **Never commit binary-derived artifacts** (see `.gitignore`): game binaries, `*.pkl`,
   `lib_strings.txt`, `decomp_*.c`, `pck/`, `shotcalc.asm`. They are regenerated by
   `analysis/regen.sh`, they are large, and `lib_strings.txt` leaks the game
   developer's build paths.
4. `analysis/gw1_model.py` and `analysis/gw1_parser.py` are **GPL-3.0** ports of Graphwar 1.
   Do not relicense them; keep their headers.

## Running things

```bash
# always works, no game files needed
python3 graphwar_curve.py "sin(x)" --start 5 2

# the oracle tests need a copy of the game in the repo root + .venv
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python analysis/difftest.py            # ~5 min, 704 cases
.venv/bin/python analysis/fuzz.py 300 7          # random expression trees
.venv/bin/python analysis/difftest_parser.py     # 90 expressions
.venv/bin/python analysis/final_verify.py        # end-to-end
.venv/bin/python analysis/discontinuity.py       # REPORT §5.7 experiments
```

Missing `libgraphwarrust.so` → `analysis/emu.py` exits immediately with a message.
Do not "fix" that by committing the binary.

## Hard facts (do not re-derive)

| item | value |
|---|---|
| entry points | parser `0x4ed670`, evaluator `0x4eb9d0`, sampler `0x3c2530`, correction `0x3c5f70` |
| token encoding | 16 bytes `{tag: u64, value: f64}`, prefix (Polish) order |
| tags | 0..17 = `x y y' + - neg * / ^ sqrt log ln exp abs sin cos tan const` |
| step (chord length) | `0.01` on the server (`0x3f847ae147ae147b`) |
| tolerance / iterations | `0.001`, at most 100 bisection steps |
| point budget | `(200.0 / step) as i32`, min 1 → 20000 at step 0.01 |
| plane bounds | `|x| <= 25`, `|y| <= 15`, checked *before* a point is accepted |
| correction | `c = y0 - f(±x0)`; the shot uses `f(x) + c` |
| parser quirks | `^` is **left**-associative; `log` = log10; `pi`/`π`/`n` = π; implicit multiplication; `+` fills missing operands with `CONST 0` |
| dead feature | the third variable `y'` is passed as `0` at **all 7** evaluator call sites |

Ghidra/REA address = ELF virtual address + `0x100000`
(file address `0x3c2530` is Ghidra address `0x4c2530`).
Reading raw bytes at a `_DAT_xxxx` seen in decompiled output requires subtracting
`0x100000`; forgetting this silently yields garbage.

**`analysis/funcstarts.pkl` is WRONG — do not use it.** It is an `.eh_frame` parse whose
13430 entries intersect Ghidra's 13503 function entries in only 2 places, and many of its
addresses are not instruction boundaries at all (its max value lies past `.text` end).
Use the Ghidra-derived table `analysis/funcstarts_ghidra_va.pkl` (already converted to
virtual-address space) instead. See REPORT §6 and the reconstruction repo's docs/02 §12.

## The reconstruction sub-repo (`gw2-rebuild/`)

A **separate git repository** (`Cmd-GZ/graphwar2-rebuild`) holds the source reconstruction and the
per-topic write-ups. Rules:

* It is git-ignored by *this* repo and must **never** be committed here. Verify with
  `git ls-files | grep gw2-rebuild` (must print nothing).
* `rsc/` (assets extracted from `Graphwar.pck`) is binary-derived and git-ignored there too;
  only the manifest is committed. Do not push game assets to a public remote.
* Its `docs/00-status.md` is the one-page state of the world; `docs/15-end-to-end.md` walks
  a shot from typed text to a dead soldier; `docs/16-reproduce.md` is the verification recipe.
* **Its `AGENTS.md` §0 is the binding standard for that half** — read it before judging any work
  there. Two rules that differ from habits in *this* repo: (a) `cargo test` / client self-test
  counts are **regression protection, never reconstruction evidence**; (b) the client under
  `client/` is a **rewritten imitation**, not the original source — the original's UI controllers
  are Rust modules inside the `.so`, so "it looks right" proves nothing.

## REA toolchain (installed 2026-11)

* `rea-agents@6.8.0` lives in `.rea-runtime/`; registered for DeepSeek Harness in
  `~/.dsh/cordis.patch.yml`.
* Ghidra **12.1.4 only** (REA refuses 12.2 — version policy is pinned to `12.1.x`):
  `GHIDRA_INSTALL_DIR=tools/ghidra_12.1.4_PUBLIC`, `JAVA_HOME=/usr/lib/jvm/java-25-openjdk`.
* First import ≈21 min; later calls in the same session are seconds. `ghidra.startup_timeout_ms`
  is a **runtime** setting that does **not** survive a restart — re-set it each session.
* Helper scripts in the reconstruction repo: `tools/callers.py`, `tools/ptr_slots.py`
  (indirect dispatch via relocations), `tools/const_xrefs.py`, `tools/pck_extract.py`.

**What REA actually is**: an MCP *bridge* that exposes reverse-engineering engines
(Ghidra, Hopper, Rizin, Frida, …) as agent tools. It is not an engine itself — so every
quirk below is a property of the **bridge**, and every conclusion still has to be justified
by evidence from the engine or the artifact.

**Known bridge trap (hit for real in 2026-11)**: pass `procedure_pseudo_code` /
`analyze_function` an address that is **not a real function entry** and it does **not**
error — it silently reinterprets the value as a *file offset* (`+0x101000`) and returns a
**completely unrelated function**. Observed: `0x6ea6dc` (a vaddr that had been
double-offset by `0x100000`) returned an SSE image-filter routine that looked plausible.

Guard rails:
1. Call `procedure_info` or `resolve_containing_procedure` **first** to prove the address
   is a function entry.
2. Check the returned `selection.mapped_address` — if it differs from the requested
   address, the result is **not** about your function; discard it.
3. Cross-check at least one decisive instruction with `objdump` before believing a
   decompiled conclusion. (Every solid result in this repo — `hi = mid2`, the 25 s budget,
   the single-parent factory — came from `objdump` or runtime observation, not pseudocode.)
4. The Ghidra session is **shared**: `start_gdb_session` / `gdb_console` / `open_binary`
   retire the active analysis session, so never run them while another agent is reading
   assembly.

**Preferred order of evidence**: existing docs → `objdump` (exact bytes) → Frida runtime
observation → REA pseudocode (only when the first three cannot give you the structure).

## Environment quirks (this machine)

| symptom | cause | workaround |
|---|---|---|
| `npm EROFS` | `~/.npm` read-only | set `npm_config_cache` inside the workspace |
| files vanish in `/tmp` | per-command tmpfs | keep artifacts in the workspace |
| cargo cannot reach registry | `~/.cargo` read-only | `CARGO_HOME=<workspace>/.cargo-home` |
| `git push` ssh error | `/etc/ssh/ssh_config.d` permissions | `GIT_SSH_COMMAND="ssh -F /dev/null"` |
| REA tool call dies at 60 s | client default | `toolCallTimeoutMs: 1800000` in the registration |
| stale build artifact silently used | several tools look for binaries in fixed places | prefer `CARGO_TARGET_DIR`; delete stale `target/`; see `gw2-rebuild/AGENTS.md` "改了但没生效" |

## Style

* Python 3.9+, no type stubs needed, docstrings explain *why* (the "why" is the whole point here).
* Chinese is fine inside `REPORT.md`; code comments in English.
* Keep `REPORT.md` sections numbered — `analysis/discontinuity.py` and the code comments
  reference them by number (e.g. "REPORT §5.7").
